One override per line, parsed as YAML, e.g. drift.policy=risk_free. Equivalent to passing --set once per line on the CLI; lines starting with # are ignored.

Reloads every panel below from this config -- universes, models, horizons and scenario names all come from it, so apply it before filling in the forms.

Fetch & validate

Both hit the network (yfinance, and optionally FRED for --risk-free/--industry).

Fetch

Downloads adjusted daily prices into the local cache (data_cache/ by default), refetching only tickers whose cache is stale. Nothing here is used until it has been fetched at least once.

Which symbols to fetch. Selecting none fetches the full configured universe plus benchmarks (--tickers is only sent when at least one chip is selected).

  • --force: refetch even if the cache is already fresh (normally an up-to-date ticker is skipped).
  • --risk-free: also download the 3-month T-bill series (FRED DTB3) that keeps backtest drift point-in-time; without it, backtests fall back to a non-point-in-time rate and the CLI warns about it.
  • --earnings: also seed the earnings-date calendar from the provider. Coverage is only a few recent quarters and timing is often missing, so review the resulting file by hand before trusting the earnings-jump model.
  • --industry: also download the semiconductor industrial-production series (FRED IPG3344S) used by the Phase 4B industry-cycle signal; its release dates are approximated, not exact.

Validate

Checks the cached data for gaps, stale runs, unadjusted splits and outliers, and writes a validation report plus a correlation heatmap. It only ever reports issues -- nothing is filled, dropped or corrected automatically.

Simulate

Fits the chosen model to cached history up to the most recent cached date and simulates a distribution of future price paths forward from there -- a fan of outcomes with probabilities attached, never a single predicted price. Produces a risk table (VaR/CVaR, probability of a loss, optionally probability of finishing above a target), a fan chart and a terminal-price histogram.

Single ticker simulates one name's own price distribution. Portfolio simulates several tickers jointly (so cross-ticker correlation, portfolio drawdown and each ticker's contribution to portfolio CVaR are computed correctly) rather than combining separate single-ticker runs.

Symbol to simulate; must have cached price history (see Fetch & Validate).

Comma-separated TICKER=weight pairs, e.g. NVDA=0.5,AMD=0.5. Weights are normalized automatically, so they don't need to add up to 1. Leave blank to equal-weight the full configured universe instead.

How many trading days forward to simulate from the last cached price (~252 per year, so 126 is roughly 6 months).

gbm: constant-volatility lognormal baseline. bootstrap: resamples blocks of real historical days. garch_t: GJR-GARCH with Student-t shocks -- volatility clustering and fat tails (one of the three models in the default backtest comparison, alongside gbm and bootstrap). earnings_jumps: a base model plus each ticker's own historical earnings-day reaction. factor: market + sector factor decomposition. factor_regime: factor model with a shared sector-wide regime switch. fhs: filtered historical simulation (resampled GARCH residuals). merton: jump-diffusion for sudden headline moves. har: range-based (Garman-Klass) volatility regression. regime: two-state Markov volatility switching. blend: mixes whole paths from several of the above. Full derivations in MODEL_NOTES.md.

Number of simulated price paths. More paths tighten the Monte Carlo error on tail statistics (see the convergence table in the results) at the cost of runtime and memory; defaults to the configured simulation.n_paths.

Random seed for the path generator. The same config and seed reproduce a run exactly; defaults to the configured simulation.seed.

Adds the simulated probability of finishing above this price to the risk table. This is one more probability alongside VaR/CVaR, not a price target; leave at 0 to skip it.

Fits the pooled regression tilt live, on top of the configured drift policy.

Requires --model gbm and a single ticker. Fetches today's option chain over the network; cannot be backtested (MODEL_NOTES §16).

Backtest

Walk-forward scoreboard. The full default universe/model/horizon set takes about 3.5 minutes (CLAUDE.md) -- this blocks until it finishes, same as the CLI.

Which models to score side by side. Each is re-fit and re-forecast at every origin below using only data available up to that origin, then judged on the same coverage/CRPS/PIT metrics -- see the Simulate panel's model list for what each name does.

Forecast horizons, in trading days, evaluated at every origin. Longer horizons compound more forecast error, so coverage is naturally looser at 252 days than at 21.

Which tickers to include in the walk-forward scoreboard.

First forecast origin. The walk-forward loop re-fits and forecasts at each origin (month-end, by default) from here to the end date, strictly using only data up to that origin.

Last forecast origin; leave blank to walk forward through the most recent cached data.

Simulated paths drawn at each origin, for each model and ticker. Kept far lower than a single Simulate run by default, since this repeats at every origin.

Random seed shared across every origin's simulations; reproducible from the same seed.

Signals

Cross-validated, pre-holdout evaluation of the Phase 4B signals. The one-time --holdout evaluation is deliberately not offered here -- it is already spent (research_log.md) and CLAUDE.md forbids re-running it. Use the CLI directly, deliberately, if that ever needs to change.

Tickers pooled into the single cross-sectional signal panel used for the regressions below.

Trading-day horizon the signals are evaluated at (from the configured signals.horizons). Reported here: single-signal and combined regressions, quantile-regression pinball loss, and coefficient stability -- all walk-forward cross-validated with a gap at least as long as the horizon, never a plain random split.

Scenario

Runs a fixed, hypothetical stress -- a sector-wide shock, a volatility spike, a specific set of ticker shocks, or a replay of a past crisis window -- through a fitted model and reports the conditional impact on price, drawdown and loss probabilities. These are "what if this happens" outcomes, not forecasts: no probability attaches to the scenario itself occurring.

Which configured stress scenario to apply (config scenarios). Kinds in the default config: sector_shock (an instantaneous sector-wide move, propagated to each ticker through its beta), vol_multiplier (a temporary volatility spike over a number of days), custom_shock (a specific per-ticker shock schedule, e.g. an export-control scenario), and historical_replay (replays a named past window's realized returns, e.g. the 2020 COVID crash). See config/default.yaml for each one's exact parameters.

Tickers the scenario is applied to; defaults to the full configured universe when none are selected.

Trading days simulated forward before the scenario's impact is measured.

The fitted return model the scenario's shock is applied on top of -- see the Simulate panel's model list for what each name does.

Number of simulated paths used to estimate the scenario's impact distribution.

Random seed for the scenario's simulation; reproducible from the same seed.

In addition to each ticker's own impact, also report the impact on an equal-weighted portfolio across the selected tickers. On by default; unchecking sends --no-equal-weight instead of omitting the flag.

Runs & reports

Every command above writes a timestamped runs/<name>/ folder holding its config snapshot, seed and output tables/figures, so any run can be reproduced or re-inspected later. This panel lists those folders and lets you view -- or build, if it hasn't been built yet -- each one's self-contained HTML report (the same one semimc report produces on the command line).
